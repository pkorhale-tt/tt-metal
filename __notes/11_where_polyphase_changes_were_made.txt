This note is a complete map of WHERE the V1 polyphase implementation of
ttnn.conv_transpose2d was added in the codebase. It is the "code archaeology"
companion to notes 08 (math & theory), 09 (implementation guide), and 10
(perf impact).

The existing ttnn.conv_transpose2d code path is COMPLETELY UNTOUCHED. Every
line we touched is either:
  - a brand-new file we created, OR
  - a small additive edit to an existing build/binding file that registers
    the new function under ttnn.experimental.

The polyphase op is exposed exclusively as:

    ttnn.experimental.conv_transpose2d_polyphase(...)

No existing import, op name, or behavior changes.

SECTION 2 - WHAT EACH NEW FILE DOES (in plain English)
--------------------------------------------------------------------------------

== A.1  conv_transpose2d_polyphase.hpp (the core orchestrator API) ==

  Path: ttnn/cpp/ttnn/operations/conv/conv_transpose2d/
            conv_transpose2d_polyphase.hpp

  Declares the C++ entry point that the experimental wrapper calls. The
  signature mirrors ttnn::conv_transpose2d so a future "is_polyphase_friendly
  -> route automatically" promotion is straightforward.

  Key declaration:

      ConvTranspose2dResult conv_transpose2d_polyphase(
          const ttnn::Tensor& input_tensor,
          const ttnn::Tensor& weight_tensor,
          MeshDevice* device,
          uint32_t in_channels, uint32_t out_channels, uint32_t batch_size,
          uint32_t input_height, uint32_t input_width,
          std::array<uint32_t, 2> kernel_size,
          std::array<uint32_t, 2> stride,
          std::variant<std::array<uint32_t, 2>, std::array<uint32_t, 4>>
              padding,
          std::array<uint32_t, 2> output_padding,
          std::array<uint32_t, 2> dilation,
          uint32_t groups,
          const std::optional<const DataType>& dtype = std::nullopt,
          const std::optional<const ttnn::Tensor>& bias_tensor = std::nullopt,
          const std::optional<const Conv2dConfig>& conv_config = std::nullopt,
          const std::optional<const DeviceComputeKernelConfig>& compute_config
              = std::nullopt,
          const std::optional<const MemoryConfig>& memory_config = std::nullopt,
          bool mirror_kernel = true);

== A.2  conv_transpose2d_polyphase.cpp (the actual algorithm) ==

  Path: ttnn/cpp/ttnn/operations/conv/conv_transpose2d/
            conv_transpose2d_polyphase.cpp

  ~300 lines. What it does, in order:

    (1) Asserts V1 preconditions (1D-as-2D: H==1, K_h==1, S_h==1,
        dilation==(1,1), groups==1, padding==0, output_padding==0).

    (2) Calls shuffle_weights_polyphase(weight, S_w) on host to produce
        a [S_w, C_out, C_in, 1, K_p] tensor where each per-phase slice
        is already in OIHW format ready for ttnn::conv2d.

    (3) For each phase p = 0..S_w-1:
          - slice_phase_weights(...) extracts the p-th sub-kernel
          - calls ttnn::conv2d with kernel_size=(1, K_p), stride=(1, 1),
            padding=(0, 0, K_p-1, K_p-1)   <-- the symmetric "same"
            padding is delivered via conv2d's own padding parameter
            (NOT ttnn::pad - we tried that and it produced wrong
             results for NHWC C=1 tensors; see note 08, debug section).
          - converts the output to ROW_MAJOR / INTERLEAVED DRAM so
            the downstream reshape/concat doesn't tangle with TILE
            structure padding.

    (4) Interleaves the S_w phase outputs into one (N, 1, T_out, C_out)
        tensor via:
              reshape each phase  (N, 1, T_phase, C) -> (N, T_phase, 1, C)
              concat dim=2        -> (N, T_phase, S_w, C)
              reshape flatten     -> (N, 1, T_phase*S_w, C)
              slice to T_out      -> (N, 1, T_out, C)

    (5) Returns ConvTranspose2dResult{ output, OH=1, OW=T_out,
                                       first_weight, first_bias }.

== B.1  experimental/.../conv_transpose2d_polyphase.hpp + .cpp ==

  Path: ttnn/cpp/ttnn/operations/experimental/
            conv_transpose2d_polyphase/

  Thin wrapper. The .cpp is ~80 lines and does nothing more than:

      ConvTranspose2dResultWithOptions conv_transpose2d_polyphase(...) {
          auto result = ttnn::operations::conv::conv_transpose2d
                            ::conv_transpose2d_polyphase(...);
          return result.output_tensor;   // V1 returns just the tensor
      }

  This separation lets us iterate on the C++ orchestrator in /conv/ without
  touching the public Python-binding surface, and vice versa.

== B.2  experimental/.../conv_transpose2d_polyphase_nanobind.{hpp,cpp} ==

  Path: ttnn/cpp/ttnn/operations/experimental/
            conv_transpose2d_polyphase/

  Pybind11/nanobind glue. Registers the function under the
  ttnn.experimental namespace:

      ttnn::bind_function(
          module, "conv_transpose2d_polyphase",
          "ttnn.experimental.",                   // <-- namespace prefix
          ...);

  (Note: the empty/missing third arg was the source of the
   "AttributeError: module 'ttnn.experimental' has no attribute
   'conv_transpose2d_polyphase'" we hit during bring-up; see note 09.)

== C.1  test_conv_transpose2d_polyphase.py (proper unit tests) ==

  Path: tests/ttnn/unit_tests/operations/conv/
            test_conv_transpose2d_polyphase.py

  Two test functions, parametrized over 4 shapes:
    - test_polyphase_correctness:  PCC vs torch.conv_transpose1d
    - test_polyphase_vs_current:   side-by-side timing/correctness vs
                                    existing ttnn.conv_transpose2d
                                    (current path skipped for shapes
                                     known to crash in op_slicing)

== Edit 2: prepare_conv_transpose2d_weights.cpp ==

  Two new function definitions appended (~80 lines total):

    bool is_polyphase_friendly(...)
        - V1 conservative heuristic. Returns true only when ALL of:
            input_h == 1, kernel_h == 1, stride_h == 1
            stride_w > 1
            kernel_w >= 4 * stride_w
            in_channels <= 64
            input_w >= 8
        - Otherwise returns false (preserves default path).

    ttnn::Tensor shuffle_weights_polyphase(...)
        - Host-side weight transform.
        - Combines in one pass:
            * IOHW -> OIHW transpose (channel-axis swap)
            * Polyphase decomposition (split K_w axis into S_w phases)
            * Cross-correlation reversal (kp -> K_p - 1 - kp)
            * Zero-padding for the trailing phase when K_w mod S_w != 0
        - Templated over dtype (bf16, fp32, uint32).
        - Output shape: [S_w, C_out, C_in, 1, K_p]

  All existing functions in this file UNCHANGED.

SECTION 5 - BUGS DISCOVERED & FIXED DURING BRING-UP
--------------------------------------------------------------------------------

Documented in detail in notes 08 and 09. Brief summary of where the fix
landed:

  Bug 1: "AttributeError: module 'ttnn.experimental' has no attribute
          'conv_transpose2d_polyphase'"
    Fix in: experimental/.../conv_transpose2d_polyphase_nanobind.cpp
    The "ttnn.experimental." string was missing from the ttnn::bind_function
    template parameter, causing the function to be registered under the
    top-level ttnn namespace instead of ttnn.experimental.

  Bug 2: "unused parameter 'out_channels'" compile error
    Fix in: conv/conv_transpose2d/prepare_conv_transpose2d_weights.cpp
    Added [[maybe_unused]] to the out_channels parameter of
    is_polyphase_friendly().

  Bug 3: ".first/.second on uint32_t" compile error
    Fix in: conv/conv_transpose2d/conv_transpose2d_polyphase.cpp
    get_pair_n4_padding(...) returns a flat std::array<uint32_t, 4>
    not an array-of-pairs. Code was accessing padding_n4[i].first/.second
    by mistake. Fixed to use padding_n4[0..3] directly.

  Bug 4: PCC = 0.0978 (TILE-layout reshape/concat scrambles W axis)
    Fix in: conv/conv_transpose2d/conv_transpose2d_polyphase.cpp
    After each phase's ttnn::conv2d, convert TILE -> ROW_MAJOR and
    sharded -> interleaved DRAM before any reshape/concat. The tile
    internal padding aliases the W and C dims, so reshapes don't
    preserve the logical element order otherwise.

  Bug 5: PCC = 0.0978 (off-by-one from wrong ttnn::pad behavior)
    Fix in: conv/conv_transpose2d/conv_transpose2d_polyphase.cpp
    Switched from "ttnn::pad first, then conv2d with padding=0" to
    "feed unpadded input to conv2d with padding=(0,0,K_p-1,K_p-1)".
    ttnn::pad on an NHWC ROW_MAJOR tensor with C=1 was producing
    right-only padding instead of symmetric padding, causing every
    phase output to be left-shifted by 1.

--------------------------------------------------------------------------------
SECTION 6 - KNOWN GAPS (V2 work)
--------------------------------------------------------------------------------

These are intentionally NOT implemented in V1. They live in note 08's
"V2 scope" section and are tracked here only so future code archaeology
matches up:

  - Bias is currently routed only to phase 0's conv2d call. For shapes
    with bias != None and S_w > 1, only 1/S_w of the output positions
    get the bias added. Fix is a one-line change in
    conv_transpose2d_polyphase.cpp:
        std::optional<const ttnn::Tensor> bias_for_call = bias_tensor;
    instead of the current:
        std::optional<const ttnn::Tensor> bias_for_call =
            (phase == 0) ? bias_tensor : std::optional<...>{};

  - V1 only supports 1D-as-2D (H == 1). Full 2D would need to also
    decompose along the H axis (S_h phases x S_w phases = S_h*S_w
    sub-convs). Most of the orchestrator structure carries over.

  - V1 only supports padding == 0 and output_padding == 0. Generalizing
    means adjusting both the input pad and the final slice bounds.

  - V1 interleaves outputs via reshape+concat+slice on DRAM tensors.
    A V2 on-device "interleave kernel" would skip the round-trip.

  - is_polyphase_friendly() is currently NOT WIRED IN to
    determine_conv_transpose2d_execution_path() - polyphase is purely
    opt-in via the experimental API. Wiring it in (auto-promote when
    the heuristic says yes) is a one-line change in
    determine_conv_transpose2d_execution_path() inside
    prepare_conv_transpose2d_weights.cpp.
