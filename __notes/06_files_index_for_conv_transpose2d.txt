================================================================================
  CONV_TRANSPOSE2D - COMPLETE FILE INDEX
  Every file in the codebase that touches conv_transpose2d, with a short
  description of what each one contains.
================================================================================

  How to use this file:
      Treat it as a "code map." When you want to know where something
      lives, search this file first. Files are grouped by role, with the
      most important ones at the top of each section.

  Convention:
      File path                                      <-- relative to repo root
      --> one-line purpose
      --> what's inside (key functions/classes)
      --> why it matters for conv_transpose2d


================================================================================
  GROUP A - CONV_TRANSPOSE2D CORE  (the op itself)
================================================================================

  ttnn/cpp/ttnn/operations/conv/conv_transpose2d/conv_transpose2d.hpp
      --> Public C++ API for ttnn::conv_transpose2d.
      --> Declares the namespace-level function `conv_transpose2d(...)`,
          the `ConvTranspose2dResult` and `ConvTranspose2dResultWithOptions`
          return types, and the `conv_transpose2d` entry point.
      --> This is the header the Python binding sees.

  ttnn/cpp/ttnn/operations/conv/conv_transpose2d/conv_transpose2d.cpp
      --> THE main implementation (~1300 lines). Heart of the op.
      --> Contains:
            - `compute_conv_transpose2d_dimensions()`
                Output H/W, full input H/W, strided H/W, real padding.
            - `determine_conv_transpose2d_execution_path()`
                Picks L1 vs DRAM path.
            - `conv_transpose2d_L1()`
                The fast path: shard input, halo, conv2d.
            - `conv_transpose2d_DRAM()`
                The slicing path for large tensors.
            - `ConvT2DSliceAttr`
                Slicing attributes for the DRAM path.
            - The top-level `ttnn::conv_transpose2d()` dispatcher.
      --> This is where the halo + conv2d decomposition happens.
          When you read just ONE file in this folder, read this one.

  ttnn/cpp/ttnn/operations/conv/conv_transpose2d/conv_transpose2d_nanobind.hpp
      --> Header that declares the Python-binding helper.
      --> Just a function decl: `void bind_conv_transpose2d(nb::module_&);`.

  ttnn/cpp/ttnn/operations/conv/conv_transpose2d/conv_transpose2d_nanobind.cpp
      --> The actual nanobind glue.
      --> Calls `ttnn::bind_function<"conv_transpose2d">(...)` so that
          `ttnn.conv_transpose2d` is exposed to Python.
      --> Also binds `prepare_conv_transpose2d_weights` and
          `prepare_conv_transpose2d_bias` from Python.
      --> Holds the Python docstrings.

  ttnn/cpp/ttnn/operations/conv/conv_transpose2d/prepare_conv_transpose2d_weights.hpp
      --> Public-ish API for the weight/bias prep helpers used both by
          the op itself and by the Python `prepare_*` entry points.
      --> Declares:
            - `ConvTranspose2dDimensions` struct
            - `compute_conv_transpose2d_dimensions(...)`
            - `transform_weights_for_conv_transpose2d(...)`
                Mirror + IOHW -> conv2d-friendly layout.
            - `prepare_conv_transpose2d_weights(...)`
            - `prepare_conv_transpose2d_bias(...)`
            - `determine_conv_transpose2d_execution_path(...)`
            - `get_conv_transpose2d_slice_attr(...)`

  ttnn/cpp/ttnn/operations/conv/conv_transpose2d/prepare_conv_transpose2d_weights.cpp
      --> Host-side weight transformation.
      --> Implements:
            - The kernel-mirror logic (`mirror_kernel=True` in PyTorch parity).
            - The IOHW -> OIHW conversion needed by conv2d.
            - Tile-izing and uploading weights to device.
            - Bias preparation.
            - The slice-attribute computation for the DRAM path.


================================================================================
  GROUP B - CONV2D ENGINE  (the underlying kernel that does the real work)
================================================================================

  ttnn/cpp/ttnn/operations/conv/conv2d/conv2d.hpp
      --> Public API for ttnn::conv2d (and the prim variant).
      --> Declares `ttnn::conv2d(...)` and `ttnn::prim::conv2d(...)`.
      --> conv_transpose2d's L1 path calls `ttnn::prim::conv2d` directly
          after halo.

  ttnn/cpp/ttnn/operations/conv/conv2d/conv2d.cpp
      --> Top-level conv2d implementation; auto-shard wrapper, prep,
          and dispatch into the device op.
      --> The DRAM-slicing path also lives here.

  ttnn/cpp/ttnn/operations/conv/conv2d/conv2d_utils.hpp
  ttnn/cpp/ttnn/operations/conv/conv2d/conv2d_utils.cpp
      --> Shared helpers used by BOTH conv2d and conv_transpose2d.
      --> Key functions:
            - `determine_parallel_config(...)`
                Computes ParallelConfig (num_cores_nhw, num_cores_c, grid)
                given a TensorMemoryLayout.
            - `determine_conv_config_for_auto_shard(...)`
                Picks HEIGHT/BLOCK/WIDTH by minimizing per-core L1 use.
                conv_transpose2d calls this when shard_layout is None.
            - `find_closest_largest_divisor_with_num_padding_and_mult(...)`
                The divisor-search that decides num_cores (the function
                that picks 62 for the iSTFT case).
            - `determine_input_memory_config(...)`, `determine_output_parallel_config(...)`
            - `get_input_channels_alignment(...)`
                Where in_channels_padded comes from (alignment to
                TILE_WIDTH or 16/8 depending on dtype).
            - `use_matmul_for_1x1_conv(...)`
                The 1x1 fast path detector.
            - `calculate_L1_usage_for_conv_op(...)`

  ttnn/cpp/ttnn/operations/conv/conv2d/conv2d_op_program_factory_common.hpp
  ttnn/cpp/ttnn/operations/conv/conv2d/conv2d_op_program_factory_common.cpp
      --> Code shared between the height-, block-, and width-sharded
          program factories.

  ttnn/cpp/ttnn/operations/conv/conv2d/conv2d_nanobind.hpp
  ttnn/cpp/ttnn/operations/conv/conv2d/conv2d_nanobind.cpp
      --> Python bindings for ttnn.conv2d. Calls `bind_conv_transpose2d`
          from the conv_transpose2d nanobind too.

  ttnn/cpp/ttnn/operations/conv/conv2d/prepare_conv2d_weights.hpp
  ttnn/cpp/ttnn/operations/conv/conv2d/prepare_conv2d_weights.cpp
      --> Shared weight-preparation utilities.
      --> Includes `convert_conv_weight_tensor_to_grouped_layout_for_conv_transpose2d`
          (used when groups > 1 in conv_transpose2d).

  ttnn/cpp/ttnn/operations/conv/conv2d/device/conv2d_device_operation.hpp
  ttnn/cpp/ttnn/operations/conv/conv2d/device/conv2d_device_operation.cpp
      --> The "device op" descriptor: validation, output specs, program
          factory selection.
      --> This is the object launched by the runtime.

  ttnn/cpp/ttnn/operations/conv/conv2d/device/conv2d_device_operation_types.hpp
      --> Shared types: `Conv2dConfig`, `Conv2dParallelizationConfig`,
          `Conv2dBlockConfig`, `Conv2dSliceConfig`.
      --> conv_transpose2d reuses ALL of these.

  ttnn/cpp/ttnn/operations/conv/conv2d/device/conv2d_op_sharded_program_factory.hpp
  ttnn/cpp/ttnn/operations/conv/conv2d/device/conv2d_op_sharded_program_factory.cpp
      --> Program factory for HEIGHT_SHARDED and BLOCK_SHARDED conv2d.
      --> Builds the program: CB allocation, kernel compilation, runtime args.

  ttnn/cpp/ttnn/operations/conv/conv2d/device/conv2d_op_width_sharded_program_factory.hpp
  ttnn/cpp/ttnn/operations/conv/conv2d/device/conv2d_op_width_sharded_program_factory.cpp
      --> Program factory for WIDTH_SHARDED conv2d.


================================================================================
  GROUP C - CONV2D ON-DEVICE KERNELS  (run on the Tensix cores)
================================================================================

  These are the kernels that actually execute on Tensix during conv2d.
  After halo expands the activation tensor, these read it from L1 and
  feed the math engine.

  ttnn/cpp/ttnn/operations/conv/conv2d/device/kernels/conv_reader_common.hpp
      --> Shared reader templates. The READER you have been investigating.
      --> Defines:
            - `read_kernel_w` -- the inner one-burst loop.
            - `read_sticks` -- iterates window positions.
            - `read_first_image_row_window`, `read_image_row_window_with_reuse`
            - `read_activation_data` -- top-level entry from each kernel.
      --> THIS IS WHERE `coalesced_read_bytes` comes from
          (line ~93/113 depending on variant). The 8 KB NoC burst limit
          appears here.

  ttnn/cpp/ttnn/operations/conv/conv2d/device/kernels/
        reader_conv_activations_padded_with_halo_3x3_weights_v2.cpp
      --> Reader kernel for HEIGHT_SHARDED conv2d (1D mcast).
      --> Computes `coalesced_read_bytes = weight_size_w * conv_act_c_read_bytes`.

  ttnn/cpp/ttnn/operations/conv/conv2d/device/kernels/
        reader_conv_activations_2d_mcast_padded_with_halo_3x3_weights_v2.cpp
      --> Reader kernel for BLOCK_SHARDED conv2d (2D mcast).
      --> Same formula; multicasts within a 2D grid.

  ttnn/cpp/ttnn/operations/conv/conv2d/device/kernels/
        reader_writer_tiled_out_1d_mcast_sender_conv_weights_tiled_col_to_rm_blocks.cpp
        reader_writer_tiled_out_1d_mcast_receiver_conv_weights_tiled_col_to_rm_blocks.cpp
      --> Combined reader+writer kernels for 1D mcast (HEIGHT_SHARDED).
          Sender drives the multicast; receivers ingest.

  ttnn/cpp/ttnn/operations/conv/conv2d/device/kernels/
        writer_tiled_out_2d_mcast_sender_conv_weights_tiled_col_to_rm_blocks.cpp
        writer_tiled_out_2d_mcast_receiver_conv_weights_tiled_col_to_rm_blocks.cpp
      --> Same pair for 2D mcast (BLOCK_SHARDED).

  ttnn/cpp/ttnn/operations/conv/conv2d/device/kernels/conv_bmm_tilize.cpp
      --> COMPUTE kernel: turns the reader's loaded data into a batched
          matmul on the math unit, with on-the-fly tilize for the output.

  ttnn/cpp/ttnn/operations/conv/conv2d/device/kernels/activation_reader_width_sharded.cpp
  ttnn/cpp/ttnn/operations/conv/conv2d/device/kernels/weights_reader_width_sharded.cpp
      --> Reader kernels for WIDTH_SHARDED conv2d.

  ttnn/cpp/ttnn/operations/conv/conv2d/device/kernels/reader_depthwise_conv1d.cpp
  ttnn/cpp/ttnn/operations/conv/conv2d/device/kernels/compute_depthwise_conv1d.cpp
      --> Specialized depthwise 1D conv kernels.
      --> Not used by conv_transpose2d directly, but live in the same dir.


================================================================================
  GROUP D - SLIDING WINDOW  (geometry, metadata, the brains of halo)
================================================================================

  ttnn/cpp/ttnn/operations/sliding_window/sliding_window.hpp
      --> Public types and helpers for the sliding-window family.
      --> Declares:
            - `SlidingWindowConfig` struct
                The is_transpose flag lives here. Drives both halo and conv2d.
            - `ParallelConfig`, `ShardBoundary`, `PixelMetadata`,
              `HaloGatherKernelConfig`.
            - Free functions: `generate_pad_metadata`, `generate_op_trace_metadata`,
              `generate_shard_boundaries`, `generate_tensor_metadata`,
              `generate_halo_kernel_config_tensors`.

  ttnn/cpp/ttnn/operations/sliding_window/sliding_window.cpp
      --> Implementation of all the above (~1200 lines).
      --> Key functions you have been studying:
            - `SlidingWindowConfig::get_output_shape()` (line 62)
                The (T-1)*stride + (K-1) + 1 formula for is_transpose=true.
            - `SlidingWindowConfig::get_transposed_full_input_shape()`
                The full_input_w = output_w + (K-1) formula.
            - `SlidingWindowConfig::get_transposed_real_padding()`
            - `generate_pad_metadata(config)` (line 220)
                The "interleaved zeros" rule for is_transpose=true.
            - `generate_op_trace_metadata(config)` (line 272)
            - `generate_halo_kernel_config_tensors(...)` (line 694)
                Builds the per-core gather/padding tables (the borrow tables).

  ttnn/cpp/ttnn/operations/sliding_window/sliding_window_nanobind.hpp
  ttnn/cpp/ttnn/operations/sliding_window/sliding_window_nanobind.cpp
      --> Optional Python bindings for sliding-window utilities.

  ttnn/cpp/ttnn/operations/sliding_window/op_slicing/op_slicing.hpp
  ttnn/cpp/ttnn/operations/sliding_window/op_slicing/op_slicing.cpp
      --> The OpSliceAttr machinery used by the DRAM path.
      --> conv_transpose2d_DRAM walks the input in slices governed by
          these attributes.


================================================================================
  GROUP E - HALO  (the data movement op)
================================================================================

  ttnn/cpp/ttnn/operations/sliding_window/halo/halo.hpp
      --> Public API: `ttnn::halo(...)`.
      --> Tiny wrapper.

  ttnn/cpp/ttnn/operations/sliding_window/halo/halo.cpp
      --> Just delegates to `ttnn::prim::halo(...)`.

  ttnn/cpp/ttnn/operations/sliding_window/halo/device/halo_device_operation.hpp
  ttnn/cpp/ttnn/operations/sliding_window/halo/device/halo_device_operation.cpp
      --> The "device op" descriptor for halo.
      --> Contains:
            - `HaloDeviceOperation` struct
            - `validate_on_program_cache_miss(...)`
            - `compute_output_specs(...)`
                Where the output shape is computed (full_input_W, etc.).
            - `create_output_tensors(...)`
            - `prim::halo(...)` (the launchable entry)

  ttnn/cpp/ttnn/operations/sliding_window/halo/device/halo_device_operation_types.hpp
      --> The `HaloParams` struct (config, parallel_config, pad_val,
          remote_read flag, max_out_nsticks_per_core, ...).

  ttnn/cpp/ttnn/operations/sliding_window/halo/device/untilize_with_halo_program_factory.hpp
  ttnn/cpp/ttnn/operations/sliding_window/halo/device/untilize_with_halo_program_factory.cpp
      --> The single program factory for halo.
      --> Allocates CBs (input, output, padding_config, gather_config),
          compiles the gather kernel, sets runtime args.
      --> Does the "untilize + pad + gather" combined work.

  ttnn/cpp/ttnn/operations/sliding_window/halo/device/kernels/dataflow/halo_gather.cpp
      --> THE HALO KERNEL that runs on every core.
      --> Functions:
            - `kernel_main()` (entry; lines 238-334)
            - `run_halo_gather<...>()` (lines 173-236)
                The route loop that issues `noc_async_write` for each
                stick to be borrowed.
            - `copy_padding<...>()` (lines 91-111)
                Splats zeros from MEM_ZEROS_BASE.
            - `write_stick_async<...>()` (lines 137-159)
            - `get_remote_core_l1_noc_addr<...>()` (lines 113-134)
                Computes the NoC address of the destination core.
      --> Has the famous `static_assert(!remote_read, ...)` that proves
          halo only uses the PUSH model.

  ttnn/cpp/ttnn/operations/sliding_window/halo/device/kernels/compute/pack_untilize.cpp
      --> Compute kernel that does the TILE -> ROW_MAJOR conversion for
          input that is in tile layout. Runs alongside halo_gather.
