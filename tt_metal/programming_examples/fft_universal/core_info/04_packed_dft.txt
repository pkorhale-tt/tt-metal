================================================================================
       SCENARIO: PATH 0 -- packed direct DFT, small N <= 32
================================================================================

Path:    fft(N) -> batched_siblings_fft(count, N) -> PATH 0
            -> packed_direct_dft_batched(N, count)
Kernel:  packed_dft_compute  (FPU matmul, fp32 inputs via HiFi4 = 4 bf16 passes)
Cores:   1 to 64, picked by Rule 2 (multiple-of-8 with rounding)

--------------------------------------------------------------------------------
WHY THIS PATH USES A DIFFERENT CORE-COUNT RULE
--------------------------------------------------------------------------------

Unlike batch_fft (which only handles power-of-2 batches), packed_dft
must handle ARBITRARY count values that come from Bluestein and
mixed-radix recursion (e.g. count = 360 for fft(3600)).

Code (fft_universal_host.cpp:351-372):
    constexpr uint32_t kRowsPerTile = 32u;
    raw_num_tiles = ceil(count / 32);    // each tile packs 32 sub-FFTs

    if (raw_num_tiles <= 7)
        num_cores = raw_num_tiles;        // 1..7 directly
    else
        num_cores = ceil(raw_num_tiles / 8) * 8;   // round up to multiple of 8
        num_cores = min(num_cores, 64);

    tiles_per_core = ceil(raw_num_tiles / num_cores);
    num_tiles      = num_cores * tiles_per_core;   // padded; extras zero

The padding rule exists because pick_batch_grid only emits valid
rectangles for num_cores in {1..7, 8, 16, 24, 32, 40, 48, 56, 64}.
Any extra padded tiles have zero input -> zero output (discarded).

--------------------------------------------------------------------------------
PACKING: 32 SUB-FFTs PER TILE
--------------------------------------------------------------------------------

A 32x32 tile holds 32 ROWS, each row is one sub-FFT input vector
of length N (with the remaining 32-N slots zero-padded):

   row 0:  [ x_0[0], x_0[1], ..., x_0[N-1], 0, 0, ..., 0 ]   <- sub-FFT 0
   row 1:  [ x_1[0], x_1[1], ..., x_1[N-1], 0, 0, ..., 0 ]   <- sub-FFT 1
   ...
   row 31: [ x_31[0], ..., x_31[N-1], 0, ..., 0 ]            <- sub-FFT 31

Each tile = 1 FPU matmul packs 32 sub-FFTs at once.
Tile-fill efficiency = N/32:
   N=2:   6.25%      N=8:  25%      N=24: 75%
   N=4:  12.5%       N=16: 50%      N=32: 100%

--------------------------------------------------------------------------------
WHAT EACH ACTIVE CORE DOES
--------------------------------------------------------------------------------

For each tile in [0, tiles_per_core):

  Reader (BRISC0):
    read in_R tile from DRAM       (real input rows packed)
    read in_I tile from DRAM       (imag input rows packed)
    read W_R tile from DRAM        (cached, shared by all cores)
    read W_I tile, W_I_neg tile    (cached, shared)
    push 4 (A,B) pairs into CB_A, CB_B

  Compute (TRISC, FPU matmul, MathFidelity::HiFi4, fp32_dest_acc=ON):
    mm_init(CB_A, CB_B, CB_OUT_R)
    // out_R = W_R*in_R - W_I*in_I  (using W_I_neg for the subtract)
    matmul_tiles(in_R, W_R)          DST  = in_R * W_R
    matmul_tiles(in_I, W_I_neg)      DST += in_I * (-W_I)
    pack_tile -> CB_OUT_R
    // out_I = W_I*in_R + W_R*in_I
    matmul_tiles(in_R, W_I)          DST  = in_R * W_I
    matmul_tiles(in_I, W_R)          DST += in_I * W_R
    pack_tile -> CB_OUT_I

  Writer (BRISC1):
    write out_R tile, out_I tile to DRAM

That's 4 FPU matmuls per tile (= per 32 sub-FFTs).
With HiFi4, each matmul is 4 bf16 passes -> 16 bf16-mul-adds per tile.
